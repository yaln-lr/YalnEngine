# YalnEngine 渲染管线接口使用说明

本文档对应当前重构后的渲染架构，目标是说明：

- `YalnRenderer` 为什么保持不变；
- 整帧策略 `IYalnFramePipeline`、逻辑 Pass `IYalnFramePass`、Vulkan PSO `IYalnPipeline`、材质 `YalnMaterial` 的区别；
- 如何在同一个场景中让不同对象使用不同材质或不同管线；
- 如何注入自定义整帧策略、追加 Pass、注册自定义 PSO；
- 如何扩展顶点格式和材质参数。

文档中的代码均按当前头文件中的真实接口编写，可直接作为接入起点。

---

## 1. 架构总览

### 1.1 四层职责

```text
YalnView
  └─ 负责初始化编排与对外门面

YalnRenderer
  └─ 稳定帧驱动器 + GPU 帧资源中心
      ├─ 命令池 / 命令缓冲
      ├─ 同步对象 / UBO / 描述符集
      ├─ YalnPipelineLibrary（PSO 注册表）
      ├─ YalnMaterialLibrary（材质注册表）
      └─ IYalnFramePipeline（整帧策略，可替换）
            └─ IYalnFramePass（逻辑 Pass，可追加）
                  └─ 通过材质解析 IYalnPipeline（Vulkan PSO）
```

关键区分：

| 名称 | 含义 | 数量级 |
|---|---|---|
| `YalnRenderer` | 稳定的帧渲染器/帧驱动器 | 每个 View 一个 |
| `IYalnFramePipeline` | 整帧怎么组织（Forward / Deferred / 自定义） | 每个 View 一个 |
| `IYalnFramePass` | 整帧中的一个逻辑阶段（Opaque / Shadow / Outline） | 每个 FramePipeline 多个 |
| `IYalnPipeline` | 某个 Pass 内实际绑定的 Vulkan PSO | 每个场景多条 |
| `YalnMaterial` | 材质参数 + 按 Pass 引用管线 | 每个场景多个 |
| `YalnDrawItem` | 一次 draw call 的输入（网格、世界矩阵、材质、Pass 掩码） | 每个可见实例一个 |

> `YalnPipeline` 仍然只表示 Vulkan PSO。  
> 整帧策略使用独立名字 `IYalnFramePipeline`，避免概念混淆。

### 1.2 默认渲染流程

`YalnRenderer::drawFrame()` 现在只做稳定的事情：

1. `scene.update(cameraPosition)` 重算世界矩阵并收集 `YalnDrawItem`；
2. 等待栅栏、获取交换链图像；
3. 打包 `YalnFrameUniform`（相机、灯光）；
4. 开始命令缓冲；
5. 构造 `YalnFrameContext`；
6. 调用 `m_framePipeline->record(context)`；
7. 结束命令缓冲并提交。

默认 `YalnForwardFramePipeline` 内部只有一个 `YalnForwardOpaquePass`。职责划分：

- FramePipeline 负责 `beginRenderPass`、清屏/深度、viewport/scissor、`endRenderPass`；
- Pass 只在当前激活的渲染通道内录制绘制命令。

`YalnForwardOpaquePass` 的行为：

1. 读取 `scene.drawItems()`；
2. 按 `pipeline → material → mesh` 排序；
3. 用材质解析管线；
4. 绑定管线、描述符集、顶点/索引缓冲；
5. 推送 `YalnMaterialPushConstants`（世界矩阵 + 材质乘色）；
6. `drawIndexed`。

## 2. 核心类型与句柄

### 2.1 句柄

定义在 `core/include/yalnrendertypes.h`：

```cpp
using YalnPipelineHandle = uint32_t;
using YalnMaterialHandle = uint32_t;

inline constexpr YalnPipelineHandle YALN_INVALID_PIPELINE = 0xFFFFFFFFu;
inline constexpr YalnMaterialHandle YALN_INVALID_MATERIAL = 0xFFFFFFFFu;

inline constexpr YalnPipelineHandle YALN_DEFAULT_PIPELINE = 0u;
inline constexpr YalnMaterialHandle YALN_DEFAULT_MATERIAL = 0u;
```

约定：

- 句柄 `0` 是默认项；
- `0xFFFFFFFF` 表示无效；
- 句柄在对应库 `clear()` 前稳定；
- 库 `clear()` 后旧句柄全部失效。

### 2.2 Pass 种类与掩码

```cpp
enum class YalnPassKind : uint32_t
{
    Shadow      = 1u << 0,
    Opaque      = 1u << 1,
    Transparent = 1u << 2,
    Outline     = 1u << 3,
    PostProcess = 1u << 4
};
```

- `YalnDrawItem::passMask`：该对象参与哪些 Pass；
- `YalnMaterialDesc::passMask`：该材质允许在哪些 Pass 使用；
- 两者按位与后包含当前 Pass，才会被绘制。

默认值 `YALN_PASS_MASK_ALL` 表示全部 Pass。

### 2.3 材质乘色

默认前向 Pass 使用以下推送常量：

```cpp
struct YALN_CORE_EXPORT YalnMaterialPushConstants
{
    glm::mat4 world{ 1.0f };
    glm::vec4 baseColor{ 1.0f, 1.0f, 1.0f, 1.0f };
};
```

默认材质 `baseColor = (1,1,1,1)`，因此重构后的默认画面与旧版本一致。  
材质乘色在片段着色器中与顶点色相乘：

```glsl
vec3 albedo = fragColor * pc.base_color.rgb;
```

## 3. 最小接入示例

大多数现有代码不需要改。`YalnView` 初始化后会自动创建：

- 默认管线句柄 `0`；
- 默认材质句柄 `0`；
- 默认 `YalnForwardFramePipeline`。

```cpp
YalnView view;

// 原有配置方式不变
YalnRenderPassConfig rpc = YalnRenderPassConfig::makeDefault();
rpc.enableDepth = true;
view.setRenderPassConfig(rpc);

YalnPipelineConfig ppc = YalnPipelineConfig::makeDefault();
ppc.depthTest = true;
ppc.depthWrite = true;
view.setPipelineConfig(ppc);

view.initVulkan("My App");

// 场景树、网格、灯光、相机接入方式不变
```

默认绘制项：

- `material = YALN_DEFAULT_MATERIAL`
- `passMask = YALN_PASS_MASK_ALL`
- `pipelineOverride = YALN_INVALID_PIPELINE`

所以旧场景默认走默认管线 + 默认材质。

## 4. 用法一：同一条管线，不同材质

适用场景：同一套光照/着色逻辑，只改颜色、粗糙度等材质参数。

```cpp
// 1. 创建材质（仍使用默认管线）
YalnMaterialDesc desc;
desc.name = "WarmWood";
desc.baseColor = glm::vec4(1.0f, 0.78f, 0.42f, 1.0f);
desc.defaultPipeline = YALN_DEFAULT_PIPELINE;

YalnMaterialHandle woodMaterial = view.createMaterial(desc);

// 2. 挂到某个节点及其整棵子树
if (YalnNode* windmill = view.scene().root()->find("windmill"))
{
    windmill->setMaterialRecursive(woodMaterial);
}
```

也可以只设置到单个绘制项：

```cpp
YalnNode* node = view.scene().root()->find("windmill.bladeA");
for (const auto& drawable : node->drawables())
{
    drawable->setMaterial(woodMaterial);
}
```

运行期更新材质参数（下一帧生效）：

```cpp
if (YalnMaterial* material = view.materialLibrary()->get(woodMaterial))
{
    material->setBaseColor(glm::vec4(0.8f, 0.9f, 1.0f, 1.0f));
}
```

要点：

- 多个材质可以共享同一条管线；
- 不同材质也可以引用不同管线；
- 材质不是管线，材质是“参数 + 管线引用”；
- 当前可运行期更新 `baseColor`；扩展为贴图/标量参数时，保持同样的“库持有实例、外部拿句柄”的方式。

## 5. 用法二：不同对象，不同管线

适用场景：同一场景中，山体走线框调试 PSO，其他对象走默认 PSO。

```cpp
// 1. 以默认配置为基础创建一条新 PSO
YalnPipelineConfig wireConfig = view.pipeline().config();

// 线框需要设备支持 fillModeNonSolid；引擎在支持时会自动启用该特性。
if (!view.device().physicalDevice().getFeatures().fillModeNonSolid)
{
    // 当前设备不支持线框，改用其他差异（例如 cullMode）或直接跳过
    return;
}

wireConfig.polygonMode = vk::PolygonMode::eLine;
wireConfig.cullMode = vk::CullModeFlagBits::eNone;
wireConfig.lineWidth = 1.0f; // >1 时需要设备支持 wideLines；引擎在支持时会启用

YalnPipelineHandle wirePipeline =
    view.createPipeline(wireConfig, "MountainWireframe");

if (wirePipeline == YALN_INVALID_PIPELINE)
{
    return;
}

// 2. 创建引用该管线的材质
YalnMaterialDesc wireMaterialDesc;
wireMaterialDesc.name = "MountainWire";
wireMaterialDesc.baseColor = glm::vec4(0.40f, 1.0f, 0.70f, 1.0f);
wireMaterialDesc.defaultPipeline = wirePipeline;

YalnMaterialHandle wireMaterial = view.createMaterial(wireMaterialDesc);

// 3. 只挂到山体
for (int i = 1; i <= 3; ++i)
{
    if (YalnNode* mountain = view.scene().root()->find("mountain" + std::to_string(i)))
    {
        mountain->setMaterialRecursive(wireMaterial);
    }
}
```

这就是“不同对象、不同管线”：

- 山体的绘制项解析到 `wirePipeline`；
- 其他对象仍解析到 `YALN_DEFAULT_PIPELINE`；
- 两者在同一个场景、同一帧中混合绘制。

## 6. 用法三：按 Pass 指定管线

如果一个材质需要在不同 Pass 使用不同 PSO，可以填 `passPipelines`：

```cpp
YalnMaterialDesc desc;
desc.name = "PBRMaterial";
desc.defaultPipeline = pbrOpaquePipeline;

// 按 Pass 覆盖
desc.setPipeline(YalnPassKind::Opaque, pbrOpaquePipeline);
desc.setPipeline(YalnPassKind::Shadow, shadowDepthPipeline);
desc.setPipeline(YalnPassKind::Outline, outlinePipeline);

YalnMaterialHandle material = view.createMaterial(desc);
```

解析优先级：

```text
YalnDrawItem::pipelineOverride
  > 材质中当前 Pass 的专用管线
  > 材质的 defaultPipeline
  > 默认管线句柄 0
```

当前默认 Forward 只执行 `Opaque` Pass。`Transparent` / `Outline` 等共享主渲染通道的阶段可以通过 `addPass()` 追加；`Shadow` 等需要离屏目标的阶段需要自定义 `IYalnFramePipeline`。

## 7. 用法四：控制对象参与哪些 Pass

```cpp
// 只参与 Opaque
node->setPassMaskRecursive(toPassMask(YalnPassKind::Opaque));

// 同时参与 Opaque 和 Outline
node->setPassMaskRecursive(
    toPassMask(YalnPassKind::Opaque) |
    toPassMask(YalnPassKind::Outline));
```

单个绘制项：

```cpp
drawable->setPassMask(toPassMask(YalnPassKind::Opaque));
```

材质也可以限制 Pass：

```cpp
desc.passMask = toPassMask(YalnPassKind::Opaque);
```

最终判定：

```cpp
if ((item.passMask & material.passMask() & currentPassBit) == 0)
{
    // 跳过
}
```

## 8. 用法五：直接覆盖管线

如果某个对象是调试对象，不想为它单独建材质，可以直接覆盖管线：

```cpp
node->setPipelineOverrideRecursive(wirePipeline);
```

或只覆盖单个绘制项：

```cpp
drawable->setPipelineOverride(wirePipeline);
```

覆盖是最高优先级。清除覆盖：

```cpp
node->setPipelineOverrideRecursive(YALN_INVALID_PIPELINE);
```

## 9. 用法六：注入自定义整帧策略

实现 `IYalnFramePipeline`，通过 `YalnView::setFramePipeline()` 注入。  
初始化前注入会在初始化时转交渲染器；初始化后注入会热替换。

```cpp
#include "yalnframe.h"

class MyFramePipeline : public IYalnFramePipeline
{
public:
    const char* name() const override { return "MyFramePipeline"; }

    bool initialize(const IYalnDevice& device,
                    const IYalnSwapChain& swapChain) override
    {
        (void)device;
        (void)swapChain;
        return true;
    }

    void shutdown() override {}

    bool recreate(const IYalnSwapChain& swapChain) override
    {
        (void)swapChain;
        return true;
    }

    void record(const YalnFrameContext& context) override
    {
        // 这里可以完全接管整帧：
        // - 开始/结束 renderPass
        // - 使用 context.pipelines / context.materials
        // - 使用 context.scene->drawItems()
        // - 录制多个子 Pass
    }
};

view.setFramePipeline(std::make_unique<MyFramePipeline>());
```

`YalnFrameContext` 提供：

```cpp
struct YalnFrameContext
{
    vk::CommandBuffer commandBuffer;
    uint32_t imageIndex;

    const IYalnSwapChain*   swapChain;
    const IYalnRenderPass*  renderPass;
    const IYalnScene*       scene;
    const YalnCamera*       camera;

    const YalnRendererConfig*  rendererConfig;
    const YalnPipelineLibrary* pipelines;
    const YalnMaterialLibrary* materials;

    vk::DescriptorSet frameDescriptorSet;
};
```

注意：

- `YalnRenderer` 负责命令缓冲的 `begin/end`；
- `IYalnFramePipeline::record()` 负责整帧内部命令；
- 默认 `YalnForwardFramePipeline` 自己开始/结束主渲染通道；
- 默认 Forward 中的 Pass 假定渲染通道已激活，不要重复 `beginRenderPass`；
- 自定义策略如果使用自己的渲染目标/多渲染通道，需要自己管理 `beginRenderPass/endRenderPass`。

## 10. 用法七：给默认 Forward 追加 Pass

默认 Forward 是可扩展的 Pass 列表：

```cpp
#include "yalnforwardpipeline.h"

class MyOutlinePass : public IYalnFramePass
{
public:
    const char* name() const override { return "MyOutline"; }
    uint32_t passMask() const override { return toPassMask(YalnPassKind::Outline); }

    bool initialize(const IYalnDevice& device,
                    const IYalnSwapChain& swapChain) override
    {
        (void)device;
        (void)swapChain;
        return true;
    }

    void record(const YalnFrameContext& context) override
    {
        // 读取 context.scene->drawItems()
        // 按 item.passMask & passMask() 过滤
        // 绑定 Outline 管线并绘制
    }
};

auto* forward = dynamic_cast<YalnForwardFramePipeline*>(view.framePipeline());
if (forward != nullptr)
{
    forward->addPass(std::make_unique<MyOutlinePass>());
}
```

`addPass()` 在 Forward 已初始化时会立即调用新 Pass 的 `initialize()`；此后交换链重建会继续调用它的 `recreate()`。

默认 Forward 的主渲染通道由 FramePipeline 统一开始/结束，追加的 Pass 会共享这个通道，适合 Overlay、Transparent、描边等“同目标叠加”阶段。

Shadow 等需要不同渲染目标/不同 RenderPass 的阶段，应实现自定义 `IYalnFramePipeline`，不要直接追加到默认 Forward。

## 11. 用法八：注册自定义 `IYalnPipeline`

如果默认 `YalnGraphicsPipeline` 不能满足需求，可以实现 `IYalnPipeline`，再注册到管线库：

```cpp
class MyPipeline : public IYalnPipeline
{
public:
    bool create(const IYalnDevice& device,
                const vk::raii::RenderPass& renderPass,
                const YalnPipelineConfig& config,
                const IYalnShaderProgram& shaderProgram) override
    {
        // 创建 descriptorSetLayout / pipelineLayout / vk::Pipeline
        // 具体实现参考 YalnGraphicsPipeline
        return true;
    }

    void destroy() override {}

    const vk::raii::DescriptorSetLayout& descriptorSetLayout() const override { return m_dsl; }
    const vk::raii::PipelineLayout&      layout()             const override { return m_layout; }
    const vk::raii::Pipeline&            handle()             const override { return m_pipeline; }
    const YalnPipelineConfig&            config()             const override { return m_config; }

    bool hasDescriptorSets() const override { return true; }
    bool hasPushConstants()  const override { return true; }
    bool isValid()           const override { return m_pipeline != nullptr; }

private:
    vk::raii::DescriptorSetLayout m_dsl{ nullptr };
    vk::raii::PipelineLayout      m_layout{ nullptr };
    vk::raii::Pipeline            m_pipeline{ nullptr };
    YalnPipelineConfig            m_config;
};

auto custom = std::make_unique<MyPipeline>();
if (custom->create(view.device(), view.renderPass().handle(),
                   view.pipeline().config(), *view.shaderProgram()))
{
    YalnPipelineHandle handle =
        view.pipelineLibrary()->addPipeline(std::move(custom), "MyPipeline");
}
```

要点：

- `addPipeline()` 接管 `unique_ptr`，库负责销毁；
- 外部生命周期由调用方保证的管线使用 `addExternal()`；
- 默认管线就是通过 `addExternal()` 登记为句柄 `0`。

## 12. 用法九：自定义顶点格式

当前 `YalnMesh` 默认仍返回 `YalnVertexPC`（位置 + 颜色）。  
但 GPU 上传已经改为通用顶点数据视图，因此可以实现自定义网格：

```cpp
struct MyVertex
{
    glm::vec3 pos;
    glm::vec3 color;
    glm::vec2 uv;
};

class MyMesh : public YalnMesh
{
public:
    const std::vector<YalnVertexPC>& getVertices() const override { return m_empty; }
    const std::vector<uint32_t>&     getIndices()  const override { return m_indices; }

    const void* getVertexData()   const override { return m_vertices.data(); }
    size_t      getVertexStride() const override { return sizeof(MyVertex); }
    size_t      getVertexCount()  const override { return m_vertices.size(); }

    glm::mat4 getModelMatrix() const override { return glm::mat4(1.0f); }
    bool isValid() const override { return !m_vertices.empty() && !m_indices.empty(); }
    size_t getCPUMemorySize() const override
    {
        return m_vertices.size() * sizeof(MyVertex) + m_indices.size() * sizeof(uint32_t);
    }

private:
    std::vector<YalnVertexPC> m_empty;
    std::vector<MyVertex>     m_vertices;
    std::vector<uint32_t>     m_indices;
};
```

创建对应管线时声明布局：

```cpp
YalnPipelineConfig cfg = view.pipeline().config();

cfg.vertexBindings = {
    vk::VertexInputBindingDescription(
        0, sizeof(MyVertex), vk::VertexInputRate::eVertex)
};

cfg.vertexAttributes = {
    vk::VertexInputAttributeDescription(
        0, 0, vk::Format::eR32G32B32Sfloat, offsetof(MyVertex, pos)),
    vk::VertexInputAttributeDescription(
        1, 0, vk::Format::eR32G32B32Sfloat, offsetof(MyVertex, color)),
    vk::VertexInputAttributeDescription(
        2, 0, vk::Format::eR32G32Sfloat, offsetof(MyVertex, uv))
};

YalnPipelineHandle myPipeline = view.createPipeline(cfg, "MyVertexLayout");
```

注意：

- 顶点布局必须与该管线实际绘制的网格格式一致；
- 索引格式当前固定为 `uint32_t`；
- 不同顶点格式使用不同管线是推荐做法。

## 13. 扩展开发指南

### 13.1 新增一种材质参数

当前材质参数只有 `baseColor`，通过推送常量上传。新增参数有两种路径：

1. **少量标量/向量**：扩展 `YalnMaterialPushConstants`，同步修改 GLSL 的 `push_constant` 块，并更新 `YalnPipelineConfig::pushConstant` 的 `size`（当前默认 80 字节 = `mat4` + `vec4`，注意 16 字节对齐）；
2. **贴图/大块数据**：给材质增加描述符集，管线配置声明对应 binding，材质库负责分配/更新描述符集。

建议先保持 `YalnMaterialDesc` 是纯数据描述，再在 `YalnMaterial` 内部持有 GPU 资源，避免把 Vulkan 句柄暴露给场景层。

### 13.2 新增一个 Pass

1. 实现 `IYalnFramePass`；
2. 在 `passMask()` 返回对应 `YalnPassKind` 位；
3. 在 `record()` 中读取 `context.scene->drawItems()`；
4. 用 `context.pipelines->get()` 解析管线；
5. 通过 `item.passMask & passMask()` 过滤对象；
6. `forward->addPass(...)` 或放进自定义 `IYalnFramePipeline`。

默认 Forward 中，Pass 假定渲染通道已激活；如果 Pass 需要自己的渲染目标，应放到自定义 FramePipeline 中，由 FramePipeline 负责 `beginRenderPass/endRenderPass`。

### 13.3 新增一种整帧技术

实现 `IYalnFramePipeline`，内部可以：

- 组合多个 `IYalnFramePass`；
- 自己创建中间渲染目标；
- 自己管理 RenderGraph；
- 复用 `YalnPipelineLibrary` / `YalnMaterialLibrary`。

`YalnRenderer` 不需要改。

### 13.4 新增一种 PSO 实现

实现 `IYalnPipeline`，然后：

```cpp
view.pipelineLibrary()->addPipeline(std::move(myPipeline), "MyPSO");
```

或者实现自定义 `IYalnPipelineFactory`（当前未内置，可在上层封装）。

### 13.5 建议的代码组织

```text
core/include/
  yalnrendertypes.h          句柄 / Pass 位 / 推送常量
  yalnframe.h                FramePipeline / FramePass / Context
  yalnpipelinelibrary.h      PSO 注册表
  yalnmateriallibrary.h      材质描述 / 材质库
  yalnforwardpass.h          默认 Opaque Pass
  yalnforwardpipeline.h      默认 Forward 策略

core/src/
  yalnpipelinelibrary.cpp
  yalnmateriallibrary.cpp
  yalnforwardpass.cpp
  yalnforwardpipeline.cpp

renderers/forward/            （后续可把默认 Forward 抽成独立插件）
```

默认 Forward 目前放在 `core` 中，但它只依赖公开接口；后续迁移到独立模块不需要改调用方。

## 14. 兼容性与迁移说明

### 14.1 `YalnRenderer` 名称与职责不变

- 类名仍是 `YalnRenderer`；
- `IYalnRenderer::initialize()` / `recreate()` / `drawFrame()` 签名保持；
- 旧调用方不需要改；
- `drawFrame()` 的 `pipeline` 参数保留用于兼容，但逐项管线选择已经下沉到材质/管线库。

### 14.2 默认行为

- 默认管线句柄 `0`；
- 默认材质句柄 `0`；
- 默认材质白色乘色；
- 默认 Forward 只含 Opaque Pass；
- 默认输出与原版本一致。

### 14.3 已知限制

- 默认 `YalnForwardOpaquePass` 只为 `hasDescriptorSets()` 的管线绑定渲染器的帧描述符集；如果自定义管线的描述符集布局与默认 UBO 布局不兼容，需要自定义 Pass 或统一布局。
- 默认 Forward 只执行 Opaque；Transparent / Outline 可以追加共享主通道的 Pass，Shadow 等离屏阶段需要自定义 FramePipeline。
- 索引格式当前固定 `uint32_t`。
- 材质当前只有 `baseColor` 参数；贴图/描述符材质需要继续扩展 `YalnMaterial`。
- 自定义顶点格式需要自定义 `YalnMesh` 覆盖 `getVertexData/getVertexStride/getVertexCount`，并给对应管线配置顶点布局。

## 17. 常见问题

### Q1：为什么不能直接给每个对象换整帧管线？

整帧管线决定“这一帧怎么组织”，一个 View 只能有一个。  
同一帧中不同对象的技术差异应该由 Pass + 材质 + PSO 表达，而不是每个对象一个 FramePipeline。

### Q2：材质和管线是什么关系？

- 材质引用管线，一个材质可以按 Pass 引用多条管线；
- 多个材质可以共享同一条管线；
- 不同对象可以通过材质使用不同管线，也可以直接用 `pipelineOverride`。

### Q3：新增对象一定要建材质吗？

不需要。默认材质句柄 `0` 会自动兜底。

### Q4：默认 Forward 的性能如何？

当前按 `pipeline → material → mesh` 排序并做简单状态缓存。  
对于更大场景，可以在 `IYalnFramePass` 内改成实例化、间接绘制或 RenderGraph，不需要改 `YalnRenderer`。

### Q5：为什么 `YalnRenderer` 不改名？

它是稳定帧驱动器，是外部依赖的锚点。  
可替换的是整帧策略 `IYalnFramePipeline`，不是 `YalnRenderer` 本身。
